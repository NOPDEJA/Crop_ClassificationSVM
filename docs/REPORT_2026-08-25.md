# Progress report — Sentinel-2 hierarchical SVM, Rayong (47PQQ)

Prepared 2026-08-24 for the 2026-08-25 meeting. Vocabulary is defined in `CONTEXT.md`;
the full study write-up is `S2_SVM_ANALYSIS.md`.

---

## 1. Summary

Three things happened since the last report.

1. **A measurement error was found in our own evaluation protocol.** The population we have
   been publishing as held out is not held out: 86.1 % of parcels contributed at least one
   pixel that a model was fitted on. Every macro-F1 in the existing write-up is measured on
   data that shares parcels with training.

2. **A corrected run was carried out** — parcel-disjoint splits, a single class-balancing
   mechanism, and the Stage-2 rejection class implemented as originally intended. On
   5,500,269 genuinely unseen pixels it reaches **macro F1 0.2248** and **weighted F1 0.8018**.

3. **The dominant lever is the class prior, not the classifier.** The same trained cascade
   moves between macro F1 0.157 and 0.205 depending only on how priors are handled at
   inference, and between 0.265 and 0.397 depending only on which population it is scored
   over. Both effects are larger than any modelling change we have made this year.

A fourth, smaller result: a hypothesis I proposed — that replacing the cascade's hard
routing with joint probability scoring would recover its routing losses — was tested and is
**wrong**. It is reported here because it was going to be a recommendation.

---

## 2. The evaluation population was not what we thought

### What we found

`S2_SVM_ANALYSIS.md` §5 defines a population called `unseen` — pixels no stage ever
sampled — and states it is "the number to publish". It covers 21.2 M rows, 87 % of the tile.

That is true pixel by pixel and misleading parcel by parcel. Pixels inside one parcel are
near-duplicates: same crop, same age, same soil, same three acquisition dates. Measuring on
a pixel whose neighbours were used in training asks "can the model recall a field it has
already seen?", not "can it identify this crop somewhere new".

Rasterising the parcel survey onto the label grid and checking which parcels contributed
fitted pixels (`build_parcel_split.py`):

| | parcels | rows |
|---|---|---|
| carrying at least one labelled row | 29,117 | 24,323,769 |
| **contributing ≥ 1 fitted pixel** | **25,084 (86.1 %)** | — |
| never fitted at all | 4,033 | **44,561 (0.18 %)** |

Genuinely clean data is **475× smaller** than what has been reported as held out. Longan has
zero clean rows; Rice has eleven.

### What it does *not* let us conclude

Scoring the existing model on those 44,561 rows gives macro F1 0.0543. **That figure should
not be quoted**, and it is not in this report's conclusions. The never-fitted parcels are
systematically tiny — median **5 pixels** against 91 for parcels that donated a fitted pixel
— because a per-pixel sampler is exponentially unlikely to miss a large parcel. The number
therefore describes an unrepresentative fringe of the tile, not the tile.

The correct response is not a cleverer audit but a retrained model on a proper split, which
is §3.

### What was built

`splits/split_assign.npy`: a parcel-atomic train/validation/test split, 61.0 / 16.4 / 22.6,
stratified by each parcel's dominant crop, verified so that **no parcel spans two folds**,
and with matched parcel-size distributions across folds (median 65 / 69 / 65 px). The 3-date
and 5-date feature matrices share row ordering, so the same split serves both arms and keeps
them comparable.

## 3. The corrected run

`train_parcel_cascade.py`, 2026-08-23 22:49 → 2026-08-24 01:32 (2 h 44 m).

Held fixed from the published arm: the three-stage hierarchy, the SVM learner, the 24
Sentinel-2 columns over Oct/Nov/Dec 2018. Changed:

| | published arm | this run |
|---|---|---|
| split | pixel-level 70/15/15 | **parcel-atomic 61/16/23** |
| fitting | caps applied before splitting | caps applied to the training fold only |
| calibration | 3-fold CV inside the training data | sigmoids fitted once on the untouched validation fold |
| balancing | caps **+** upsampling **+** `class_weight='balanced'` | **caps only** |
| Stage 2 | four-way in name; the fourth class was unreachable | genuinely four-way — **1,404,792 sink training rows** |
| Stage 3 | trained only on pixels Stage 2 routed *correctly* | trained on true crop membership |
| scoring | all 24.3 M pixels | the 5.50 M test-fold pixels only |

Hyperparameters were **frozen** at the values the previous searches selected, because the
searches themselves cross-validated at pixel level and would have reintroduced the leak.
This also removed the dominant computational cost.

### Result

| | rows | macro F1 | weighted F1 |
|---|---|---|---|
| **parcel-disjoint, hard routing** | 5,500,269 | **0.2248** (95 % CI 0.2071–0.2389) | **0.8018** |
| parcel-disjoint, joint routing | 5,500,269 | 0.1949 (0.1792–0.2068) | 0.7725 |

Confidence intervals are bootstrapped over the 5,824 **test parcels**, not over pixels; a
pixel bootstrap would report intervals far narrower than the evidence supports.

### The headline hides the actual result

Macro F1 is statistically indistinguishable from the previously published 0.2245. The
per-crop picture is not:

| crop | test support | precision (old → new) | F1 (old → new) |
|---|---|---|---|
| Oil palm | 89,353 | 0.194 → **0.828** | 0.251 → **0.498** |
| Rubber | 3,235,887 | 0.966 → 0.888 *(recall 0.659 → **0.866**)* | 0.783 → **0.877** |
| Durian | 73,052 | 0.180 → 0.361 | 0.269 → **0.380** |
| Pineapple | 139,979 | 0.349 → 0.397 | 0.440 → 0.430 |
| Rice | 49,838 | 0.348 → 0.571 *(recall 0.584 → 0.305)* | 0.436 → 0.398 |
| Cassava | 178,464 | 0.274 → 0.372 | 0.358 → 0.323 |
| Mango | 13,346 | — | 0.084 → 0.017 |
| Mangosteen | 4,122 | — | 0.058 → 0.001 |
| Rambutan, Coconut, Longan, Jackfruit, Langsat | 1,625–10,054 | — | → **0.000** |

*(The two columns differ in population as well as configuration, so this is a description of
two operating points, not a controlled measurement of any single change.)*

Removing the artificial balancing did exactly what was predicted from the error analysis:
**precision on the commercially dominant crops improved sharply** — oil palm precision more
than quadrupled, rubber recall rose 21 points, weighted F1 went 0.70 → 0.80. The price is
that **seven rare crops now score exactly zero**. Under natural priors, at a true class
imbalance of 6,685:1, the model stops emitting them at all.

So this is not a better model or a worse one. It is the far end of a dial, and macro F1 —
an unweighted mean over 13 classes of wildly different prevalence — conceals the whole
trade by averaging a large gain on six crops against a total collapse of seven.

## 4. The class prior dominates everything else we have tried

Three measurements of the same 13-crop macro F1, differing only in how priors are handled
at inference or how the model was trained. All three use the identical construction — every
row retained, non-crop truth mapped to 0 so false positives count:

| regime | population | macro F1 | crops alive |
|---|---|---|---|
| trained balanced, argmax at inference *(published arm)* | pixel held-out | 0.157 | 13 (all weak) |
| trained balanced, **post-hoc prior correction** at the swept optimum α₂ = 0.8, α₃ = 0.8 | pixel held-out | **0.205** | **13** |
| trained on natural priors, argmax *(this run)* | parcel-disjoint | **0.225** | **7 of 13** |

The 256-cell sweep on the current arm is now complete (`runs/s2_2018_3date_v2/sweep/`).
Unlike the earlier arm — where correction could not beat a better-fitted model — here it
lifts macro F1 by roughly 30 % **while keeping every crop alive**, which is precisely what
the natural-prior training regime fails to do. The two approaches trade against each other:
correction reaches a lower peak but loses no class; natural priors reach a higher peak by
abandoning seven.

*(A caution on reading the sweep's own output: `sweep_results.csv` reports several macro-F1
columns over different populations — `econ13_macro_f1` at the optimum is 0.243, not 0.205.
The figures above are all `crop_macro_f1_flat`, the column whose construction matches the
corrected run, so that the three rows are comparable. Mixing those columns would repeat the
error described in §2.)*

And scoring population alone, with the model completely unchanged:

| population | accuracy | macro F1 | weighted F1 |
|---|---|---|---|
| natural tile | 0.6988 | 0.2654 | 0.7369 |
| capped at 200,000 px per class | 0.5442 | **0.3965** | 0.5520 |

**Conclusion.** Prior handling and evaluation population move the result more than any
architectural change tested this year. The next run should combine the parcel-disjoint
protocol of §3 with the prior correction of §4 — they address the same dial from opposite
ends and have never been applied together.

## 5. A recommendation that turned out to be wrong

The cascade loses roughly 30 % of true economic pixels to irreversible early routing
decisions. I proposed replacing hard argmax routing with joint scoring —
P(econ) × P(group | econ) × P(crop | group) — so an uncertain pixel would no longer be
discarded by a single early decision.

Tested on identical models, varying only the decision rule, it is **worse**: macro F1 0.1949
against 0.2248, with non-overlapping confidence intervals, and it kills one further class.
Because it varies one thing only, this is the sole cleanly attributable result of the run.

The likely reason is that the multiplied probabilities are not comparable across branches —
the three Stage-3 experts are calibrated on different populations, so their outputs are not
on a common scale. Hard routing at least commits to one branch before comparing within it.

## 6. Comparison with the XGBoost study

Reviewing the collaborator's repository directly (`github.com/Gunkartan/geospatial`)
corrected several statements in our own §7, which had been written from second-hand notes:

- Their crop model is a **flat 14-class classifier**, not a stage of a cascade. There is no
  composed cascade in the repository — the water, buildings and crop models are trained
  independently and never chained.
- Feature sets differ more than recorded: theirs is NDVI, EVI, NDWI, MTCI and raw long-SWIR
  over the same three dates (15 columns) against our 24. Their "NDWI" is the MNDWI form and
  is not the same index as ours despite the shared name.
- Neither crop model uses texture features. (Their water and buildings detectors do; those
  do not feed the crop model.)
- Both studies split at pixel level, so **the leakage described in §2 affects both arms
  equally**. It is a shared limitation of the joint paper, not a weakness of one side.

**The issue to settle before any joint table.** Their metrics are computed over a sample
capped at 200,000 pixels per class; ours over the natural tile. As §4 shows, that difference
alone is worth +0.131 macro F1 with the model held constant, and it moves accuracy and
weighted F1 in the opposite direction. Until one evaluation population is agreed, a
side-by-side table would compare measuring sticks rather than methods. A script implementing
their protocol against our predictions already exists and can serve as the shared basis.

## 7. Corrections to our own record

Found by code review and verified against source; all are now fixed or documented:

| | |
|---|---|
| Stage 3 trained only on correctly-routed pixels | experts never saw the contaminants they must reject |
| Stage 2's fourth class was structurally unreachable | the model described as four-way was three-way; the rejection class now has 1.4 M training rows |
| No scoring metric set in any hyperparameter search | all five models were selected by **accuracy**, while the study argues macro F1 is the honest metric |
| Calibration and search cross-validated at pixel level | the leak reached model selection, not just the outer split |
| `MIN_UPSAMPLE_TRIGGER` passed but never read | the documented 0.67 condition had no effect |
| Prediction chunking needed 9.6 GB per transform | would have exhausted memory at full scale |

The first two are the substantive ones: both directly manufacture the false positives that
had been limiting precision.

## 8. Limitations

1. **The corrected run changes five things at once** — split, balancing, sink, Stage-3
   population, calibration. Only the routing ablation (§5) isolates a single variable.
2. **Rare crops have very little validation data** under an honest split: Langsat has 1,639
   training / 13 validation / 191 test pixels. No confident per-class claim should be made
   for Langsat, Coconut or Rambutan; the pixel split was concealing this behind near-duplicate
   neighbours.
3. **The split balances parcel counts, not pixel counts**, so fold supports vary widely
   (Rubber 7.25 M / 1.84 M / 3.24 M). The result is honest for this test fold but
   composition-specific.
4. **Frozen hyperparameters** were selected under the old leaky protocol. They cannot bias
   the test score, but they may be suboptimal for natural priors.
5. Labels remain the 2018 survey; the mixed-crop compound codes are still excluded.

## 9. Proposed next steps

1. **Combine §3 and §4** — parcel-disjoint training with prior correction applied at
   inference. This is the single highest-value run available and has never been done.
2. **Set `scoring='f1_macro'`** in the searches and re-tune under parcel-grouped
   cross-validation, so model selection optimises the metric we actually report.
3. **Agree one evaluation population with the collaborator** before any joint table.
4. **Temporal-difference features** from the existing three dates — the only untried source
   of new information that stays inside the paper's controlled acquisition window.
5. Re-run the 5-date arm under the same protocol; the split is already reusable.

Deliberately deferred: parcel-level aggregation of predictions (changes the unit of analysis
and would break comparability with the XGBoost study), and per-class decision thresholds
(cannot be tuned honestly for the crops that most need them, given the validation supports
in limitation 2).
